项目背景

为什么做这个网站

在校大学生在求职准备阶段普遍面临四类障碍：

信息分散

校招、实习信息散落在公众号、招聘 App、学校就业网和学长学姐的转发里，缺乏统一入口，检索成本高。

规划指导不足

低年级同学不清楚自己的职业兴趣方向，学校职业规划课程覆盖面有限，缺少可量化的自我评估工具。

简历缺乏参考

第一次写简历时不知道结构怎么排、经历怎么描述，网上模板要么收费要么排版混乱，导出后格式容易错乱。

实习渠道有限

实习岗位获取渠道少，投递后又难以跟踪进度，不知道简历是否被查看，容易陷入「投了没有任何反馈」的循环。

调研与测试

怎么做调研与测试

调研方法

  • 问卷调查：三轮共回收 200+ 份有效问卷，定位高频痛点与筛选维度需求。
  • 深度访谈：每轮访谈 8-15 名不同年级、不同专业的在校生。
  • 竞品分析：对比主流招聘 App 与高校就业网的信息组织方式。
  • 需求排序：按「提及频次 × 影响程度」对需求打分，决定迭代优先级。

测试方式

  • 可用性测试：每轮邀请用户完成任务脚本，记录完成率与耗时。
  • 接口测试：覆盖 9 个 API 的正常与异常路径（400/404/409）。
  • 功能回归：核心链路「筛选 → 详情 → 投递 → 查询」全流程回归。
  • 响应式检查：1440 / 1024 / 720 三档宽度的布局验证。
技术实现

技术栈与环境

层次技术选择说明
后端Python 标准库 HTTP Server零第三方依赖，开箱即用，便于部署与演示
数据存储SQLite单文件数据库，首次启动自动建表并灌入演示数据
前端原生 HTML / CSS / JavaScript无构建步骤，直接由后端静态服务托管
接口风格REST + JSON统一返回 {code, msg, data} 结构
本地存储localStorage保存简历草稿与测评结果，刷新后不丢失
账号与鉴权PBKDF2-HMAC-SHA256 + 签名 Cookie密码加盐哈希存储，会话用 HMAC 签名的 HttpOnly Cookie（12 小时有效），未登录访问返回 401 / 跳转登录页
部署方式0.0.0.0 监听 + 反向代理局域网内其它电脑用 http://本机IP:8080 访问；公网经 Cloudflare Tunnel / nginx 反代，设 CC_HTTPS_REDIRECT=1 自动跳 HTTPS
